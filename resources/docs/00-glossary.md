# 00 · 术语表

读 05 以后的章节之前，先过一遍这里。每个词都配了**为什么需要它**——
只知道定义不知道动机，看到配置项时还是不知道该不该开。

---

## 一、角色与拓扑

### 落地（landing）

用户的流量**最终从这台机器出去**访问互联网。它认证用户、按用户记流量。
用户在客户端里选的"日本01""新加坡02"，通常就是一个个落地。

### 中转（relay）

夹在用户和落地之间的一台机器。用户连它，它把字节原样搬给落地。

**为什么要中转**：用户到落地的直连质量可能很差（绕路、丢包、被干扰）。
中转放在离用户近、线路好的地方（比如香港），用户连香港、香港再走优质专线到日本，
整体比直连日本快且稳。

**`[!!]` 中转不认证用户、不持有用户名单。** 它只搬字节，看不懂里面是什么
（用户的加密在落地才解开）。这是硬边界：中转机往往是租来的、最容易被接管的那台，
而一份用户名单加凭据就是整个服务的钥匙。项目里管这条叫 **D-1**。

### L4 透传

"第四层"指 TCP/UDP 这一层。L4 透传 = 只看"这些字节要送到哪台机器的哪个端口"，
不拆开看内容。中转干的就是这个，所以它不需要、也拿不到用户凭据。

### 落地 / 中转，怎么在面板里区分

节点的**角色**字段。中转类角色（relay/springboard/front）的特征：
`port` 恒为 0（它的监听端口来自转发规则，不在节点上配）、不进任何人的订阅。

## 二、协议栈

一条代理连接从外到内是好几层，配置项分别对应不同层，混在一起看会很乱：

```
传输层   tcp / ws / grpc / xhttp     ← "字节怎么运"
安全层   none / tls / reality        ← "怎么伪装与加密"
协议层   vmess / vless / trojan      ← "怎么认出这是哪个用户"
流控     xtls-rprx-vision            ← 可选，减少一层重复加密
```

### vmess / vless

两种代理协议，都用来回答"这个连接属于哪个用户"。

- **vmess**：老一些，自带加密与时间戳校验，配置简单，**最适合先跑通**
- **vless**：新一些，**自身不加密**——把加密交给下面的安全层（TLS/REALITY）做，
  省掉一次重复加密，更快。代价是**必须**配安全层，裸奔的 vless 等于明文

### trojan

伪装成普通 HTTPS 的协议。需要真实域名和证书。

### xtls-rprx-vision（"vision 流控"）

`[!]` 不是一个协议，是 vless 的一个**选项**。

**解决什么**：TLS 里再套一层 TLS（"套娃"）会产生可识别的流量特征，而且多一次加解密。
vision 让内层数据在握手之后直接走，不再重复加密。

**代价**：它挑食——只能用在 **vless + tcp + (tls 或 reality)** 上。
换成 ws/grpc 传输就用不了。

`[!!]` **和 Mux（多路复用）互斥**。开了 Mux 的客户端连 vision 节点，
症状是"连上立刻断"。

### XUDP

vision 下 UDP 的封装方式：把 UDP 数据包**塞进那条 TCP 连接里**运。

**为什么要知道这个**：它解释了"UDP 能不能穿中转"这个问题——
用户的 UDP 是包在 TCP 里的，中转从头到尾**只看见 TCP**，所以能穿。
（`[D]` 实测见 `compatibility/udp-through-relay.md`）

## 三、REALITY 相关

### REALITY

一种伪装方式。**解决什么**：一个自建代理服务器，证书是自签的、
或者域名是新注册的，主动探测一下就露馅了。

REALITY 的做法是**借用一个真实网站的握手**：
- 正常用户（握手里带着正确的密钥）→ 服务端认出来，转给代理
- 探测者（没有密钥）→ 服务端把连接**原样转发给那个真网站**，
  探测者看到的就是那个网站真实的证书和响应

所以从外面看，这台机器"是"那个网站。

### dest（借用的目标站）

被借用的那个真实网站。REALITY 握手不成时，流量就转给它。

**选它有讲究**（详见 [06](06-reality.md)）：要支持 TLS 1.3、要能协商 X25519、
要有 HTTP/2、不能是 CDN、还要**够冷门**——用烂了的站（比如各种教程里的默认值）
本身就成了特征。

### SNI / server_names

SNI 是 TLS 握手时客户端**明文**告诉服务器"我要访问哪个域名"。
REALITY 场景下，客户端的 SNI 填的是 dest 的域名——这样在链路上看，
就像在访问那个网站。

`server_names` 是服务端的白名单：只接受 SNI 在这个名单里的连接。

### 公钥 / 私钥 / short-id

REALITY 用一对密钥认出"自己人"：

| | 在哪 | 能不能泄露 |
|---|---|---|
| **私钥** | 只在节点上 | `[!!]` 绝对不能。它进订阅或日志就等于伪装失效 |
| **公钥** | 在订阅里，给客户端 | 可以，客户端必须有 |
| **short-id** | 两边都有 | 半公开，它在每个用户的订阅里 |

`[!]` 重新生成密钥对 = **所有老客户端立刻连不上**，直到他们更新订阅。

### uTLS / 指纹（fingerprint）

TLS 握手的细节（加密套件顺序、扩展顺序）会暴露"你用的是什么软件"。
Go 写的程序握手起来不像浏览器，一眼可辨。

uTLS 让代理客户端**模仿浏览器的握手指纹**（配置里的 `chrome` 就是这个意思）。
REALITY 依赖它——伪装成某网站，却用一个"不像浏览器"的指纹去握手，等于白伪装。

## 四、中转相关

### 转发规则（forward rule）

告诉中转："在哪些机器上、监听哪个端口、把收到的东西转给谁"。
一条规则 = 一个**入站** + 若干**出站**。

### PROXY protocol

**解决什么**：中转透传之后，落地看到的源 IP 是**中转的地址**——
所有用户看起来都来自同一个 IP，在线 IP 统计和审计就全废了。

PROXY protocol 是在每条连接**最前面加一小段头**，写明"这条连接真实来自哪个 IP"。

**`[!!]` 必须两端成对**：中转发头、落地收头。只有一端配了的话：

| 情况 | 结果 |
|---|---|
| 中转发头、落地不收 | 落地把那段头当成协议数据 → 连不上 |
| 中转不发、落地要收 | 落地等一个永远不来的头 → 连不上 |

而且**两端都不会报错**——中转日志正常、落地一行都没有，只有客户端知道。
面板的规则页会做配对校验，那是唯一能在出事**之前**发现它的地方。

`[!!]` **PROXY 头没有认证**。谁能连到落地那个端口，谁就能随便声称自己是任何 IP。
所以开了收头的落地**必须只对中转可达**（防火墙锁死）。

## 五、面板侧

### mod_mu

节点和面板之间说话用的一套 HTTP 接口，源自 sspanel-uim。
节点靠它拉配置、拉用户名单、上报流量。详见 [07](07-api-node.md)。

### 节点 secret

每个节点一串随机字符，相当于这个节点的密码。节点调 mod_mu 接口时要带上。

`[!!]` 泄露了就在面板节点页重置——**但重置后要同步改节点上的配置**，
否则那个节点立刻失联。

### 订阅（subscription）

一条给用户的 URL，客户端定期去拉，得到"当前有哪些节点、怎么连"。

**为什么不是让用户手填**：节点会增减、地址会变、REALITY 密钥会轮换——
订阅让这些变化自动到达客户端。

`[!!]` 订阅里给的是**客户端要连的那一跳**：落地挂在中转后面时，
给的是中转的地址和端口，不是落地自己的。

### 等级门槛（node_class）

节点的可见门槛。用户的等级 ≥ 节点的等级门槛，才能在订阅里看到它。
`0` = 所有人可见。

`[!]` 后台表单的**取值范围是 0–9**（对应套餐等级）。

### 怎么藏一个测试节点

`[!!]` **用「禁用」（`enabled = false`），不是用很高的等级。**

- 禁用的节点**照常拉配置、照常跑、照常上报** —— `mod_mu` 那侧不看这个字段
- 但它**不进任何人的订阅**，也不出现在用户的节点列表里

也就是说：你可以让一台节点完整地跑着、心跳正常、随时能验证，同时对用户
完全不可见。这正是测试节点要的。

拿等级去藏是个坏主意：等级是给套餐分层用的，把它当可见性开关会让
"谁能看到什么"变得难以解释，而且上限只到 9。

### 倍率（traffic_rate）

计费倍数。`1` = 用多少算多少；`2` = 用 1G 扣 2G（贵线路用）；
`0.5` = 打折（冷门线路引流用）。

## 六、运维词

### 心跳

节点定期告诉面板"我还活着、现在负载多少"。面板据此显示在线/离线。

### `/health` 与 `/ready`

`[!!]` 不是一回事：

- `/health` = **进程活着**
- `/ready` = **能真正服务**

REALITY 节点的 dest 挂掉时，端口照常监听、`/health` 照常 200，
但没有任何客户端能完成握手——这时 `/ready` 会失败。
编排系统要看 `/ready`。

### 持久化重试队列

上报流量失败时，数据先存到磁盘，面板恢复后补报。
**为什么要有**：面板短暂不可用不该导致丢账。节点重启也不丢。
