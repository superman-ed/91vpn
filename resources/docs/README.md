## 这是不是"保姆级"教程

**部分是。** 说清楚差在哪，比含糊地说"是"有用：

| 保姆级通常意味着 | 我们有没有 |
|---|---|
| 每条命令可直接复制 | ✅ 有，且都在真机上执行过 |
| 每步写清"你应该看到什么" | ✅ 有 |
| 出错时怎么办 | ✅ 每篇末尾有「现象 → 查什么」 |
| 不含需要自己替换的占位符 | ⚠️ 其余章节有，但 [11 · 完整演练](11-worked-example.md) 把它们全部换成了具体值 |
| **截图** | ❌ **没有**。面板与 Cloudflare 的界面操作只有文字描述 |
| 不假设任何前置知识 | ❌ 假设你会用 SSH、知道怎么买 VPS 和域名 |

`[!]` 没有截图是这套文档最大的短板，尤其是 Cloudflare 后台那段 ——
它的界面改版很勤（"Public Hostname" 已经改叫 "Published application routes"）。
文字描述的好处是不会因为界面换皮就过期，代价是你得自己在界面上找。
找不到时按"它是干什么的"去找，别死抠字面。

## 约定

文档里的标注沿用项目惯例：

| 标记 | 含义 |
|---|---|
| `[D]` | 动态验证过（真的跑起来看到了） |
| `[S]` | 静态确认（代码/二进制里读到的） |
| `[I]` | 推断，尚无直接证据 |
| `[?]` | 未知或未验证 |
| `[!]` | 值得注意的坑 |
| `[!!]` | 踩过的坑，或配错会静默出事的地方 |

`[!!]` 标记的段落**不要跳读** —— 它们记的都是"看起来正常、实际不对"的情形，
而这类问题不会自己暴露。

## 这份文档核对过什么

写完之后逐项对着代码与真机核对过，而不是凭印象写的：

- 配置键逐个比对 `agent/internal/config/load.go`
- 指标名逐个比对 `agent/internal/metrics/names.go`
- `install.sh` 的参数逐个比对脚本本身
- 观测端点在真节点上实际请求过（`/health` `/ready` `/metrics` 均 200）
- 引用到的文件路径逐个确认存在

`[!]` 核对中查出两处我写错的地方：把 `api_addr` 写成了配置文件的键
（它其实是 `install.sh --api-addr`），以及凭印象写了几个并不存在的指标名。
**文档里错误的命令比没有文档更糟** —— 照着抄却跑不通，人会先怀疑自己的环境。
