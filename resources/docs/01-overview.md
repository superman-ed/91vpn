# 01 · 系统总览

## 这是什么

一套**机场/代理服务的节点侧基础设施**，由两部分组成：

- **Agent**（Go）：跑在节点机上，从面板拉配置与用户、管理代理内核、上报流量与状态
- **面板**（Laravel）：用户、套餐、订单、订阅，以及节点管理与中转编排

Agent 与面板之间走 **sspanel-uim 的 mod_mu 契约**（见 [07](07-api-node.md)），
所以它能对接任何实现了该契约的面板，不限于本项目的面板。

## 与 soga 的关系

本项目的 Agent 是 **soga 的独立实现**，不是它的分支或修改版：

```
目标 soga（stripped Go 二进制）
      ↓  逆向
行为规格（docs/SOGA-BEHAVIOR-SPEC.md）
      ↓  重新设计
独立实现（agent/）
      ↓  对照
兼容性测试（compatibility/）
```

`[D]` 已验证：真 soga 与本 Agent 打同一个面板时，**端点集合与调用比例一致**，
心跳字段本 Agent 是超集（见 [10](10-compat-soga.md)）。

## 部件

```
                        面板 (Laravel)
                    ┌─────────────────────┐
       用户 ────────│ 订阅 / 客户端 API   │
                    │ 节点管理 / 转发规则 │
                    └──────────┬──────────┘
                               │ mod_mu (HTTP)
                    ┌──────────┴──────────┐
                    │       Agent         │
                    │  面板适配 / 状态机  │
                    │  用户同步 / 上报    │
                    │  内核管理 / 观测    │
                    └──────────┬──────────┘
                               │ 进程内
                    ┌──────────┴──────────┐
                    │    Xray 内核        │
                    └─────────────────────┘
```

Agent **把 Xray 作为库嵌入**，不 fork 子进程（见 `docs/decisions/ADR-005`）：
配置变更不必重启进程，内核崩溃也不会留下孤儿进程。

## 两种节点角色

| 角色 | 认证用户 | 持有用户名单 | 端口来自 | 进用户订阅 |
|---|---|---|---|---|
| **落地**（landing） | 是 | 是 | 节点自身配置 | 是 |
| **中转**（relay / springboard / front） | **否** | **否** | 转发规则 | 否（订阅发的是它的入口地址） |

`[!!]` **D-1：中转不认证用户，因此绝不接收用户名单与凭据。**
这是硬边界，不是优化 —— 中转机往往是租来的、最容易被接管的那一台，
而一份用户名单加凭据就是整个服务的钥匙。面板在读写两个方向都有守卫，
详见 [05](05-relay.md)。

## 相比 soga 的改进

| 方面 | 说明 |
|---|---|
| 状态同步 | 只下发**变更**，不是每次全量重建（ADR-001） |
| 上报可靠性 | 失败进**持久化队列**，面板恢复后补报，不丢账（ADR-004） |
| 计量口径 | 按**线路字节**计量，与机房账单口径一致（ADR-006） |
| 校验 | 配置非法**启动即失败**，不静默降级（ADR-003） |
| 可观测 | `/health` `/ready` `/metrics` 三个端点（见 [09](09-ops.md)） |
| 中转 | 转发规则、健康检查、PROXY protocol 配对校验（见 [05](05-relay.md)） |
