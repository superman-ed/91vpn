# D-7 · 域名分配

**日期：** 2026-09-24
**状态：** 已定（含一项**已知并接受**的自检 warn）

---

## 决定

```
曝光度                域名            用途                        封了的后果
────────────────────────────────────────────────────────────────────────────
最曝光(牺牲域)        91vpn.com       官网/落地页,广告+SEO        只少新客
                      91vpn.cloud     官网备用                    同上
────────────────────────────────────────────────────────────────────────────
低调                  91app.shop      app.   用户面板+客户端API   收不到钱
                                      summer. 后台                 你自己进不去
                                      sub.    订阅                 换不了节点/加不了设备
────────────────────────────────────────────────────────────────────────────
高危(随时可弃)        marveo.fun      入口域,承载真实代理流量     换一条 A 记录
```

`[S]` 出处：`.env`（`APP_URL` / `ADMIN_HOST` / `SUB_URL_BASE`）、
`app/Http/Middleware/AdminHost.php`、`app/Models/EntryDomain.php`。

## 已知并接受：面板与订阅同一个可注册域

`[S]` 后台「上线自检 → 订阅地址」会**长期显示 warn**：
`sub.91app.shop` 与 `app.91app.shop` 的可注册域都是 `91app.shop`。
判断在 `ServiceReadiness::sameRegistrable()`。

**这不是待办，是选择。** 代价与收益：

| | 得到 | 失去 |
|---|---|---|
| 维持同域（现状） | 客户端不用发新版；节点不用重配 | `91app.shop` 被封时，面板和订阅**一起**失效 |
| 分成两个注册域 | 被封时只死一半 | 见下 |

### `[!!]` 为什么"分开"不像看起来那么便宜

分开有两个方向，代价**极不对称**：

```
搬面板  →  客户端要发新版 + 全员升级
搬订阅  →  用户重新导入一次订阅
```

`[S]` 面板域名写死在**每一个已安装的客户端二进制**里 —— `routes/api.php` 里
客户端要调 `/auth/login`、`/auth/register`、`/plans`、`/order/{id}/pay`、
`/user`、`/servers`、`/devices`、`/wallet` 等等。
而用户往往正是从面板下载新版：面板域一死，**连发新版这条路也断了**。

`[S]` 节点侧同理但可控：`RelayDeployController.php:99` 把
`config('app.url')` 作为 `api_url` 写进节点配置，节点是你自己的，可以逐台重配。

**所以如果将来真要分开，搬的是订阅，不是面板。** 别搞反。

### `[!]` 顺带否掉的一个方案

最初的想法是「把面板搬到 `91vpn.com`」。**这是反向的**：
`91vpn.com` 的用途就是投广告、做 SEO、被搜索引擎收录 ——
它是所有域名里**最可能先被举报/被封**的那个。
把「封了就收不到钱」的面板挂在「设计上就要被曝光」的域名下，
比现状更糟，不是更好。

### `[!]` 以及为什么不用 `91vpn.space/.store/.fun/.shop`

`[D]` 这四个已注册但停在 Hostinger（NS 是 `*.dns-parking.com`）。
更要紧的是：**它们都能从品牌 30 秒枚举出来**。
封 `91vpn.com` 的人顺手就能把这一串一起封掉 ——
用品牌域做"备用"等于没备用。真要另立一域，得是**非品牌**的。

---

## 什么情况下该重新考虑

- `91app.shop` 出现被墙/被污染的实测迹象（不是猜测）
- 客户端具备**运行时可配置 API 地址**的能力 —— 那时"搬面板"的代价从
  "发新版"降到"下发一条配置"，天平会反过来
- 开始投放规模化广告，`91vpn.com` 真的被举报，需要验证隔离是否生效
