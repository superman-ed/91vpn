## 怎么发生的

提交信息只描述了「停止按 IP 踢人」这一件事。

## 为什么要单独记这一笔

`[!!]` 后果不是代码错，是**历史会骗人**：将来有人查 `DeviceToken` / `ClientToken`
是怎么来的、为什么这么设计，`git log` 会把他带到一个讲「停止按 IP 踢人」的提交上。
**那套认证设计因此从来没有以自己的名义被审过。**

`[!]` 本仓库有过一模一样的先例：`baae7f0`（标题「activate() 锁内复查订单状态 L-10」）
里塞进了整个 `EntryDomainTest.php` 与入口域名的角色校验 —— 那条校验后来
挡住了直连落地登记入口域名，卡了 L-19，而没人知道它是什么时候、以什么理由加的。
见清单 L-19 与 `docs/decisions/entry-dispatch.md`。

## 为什么不拆开重提

拆分做过了，内容验证为**与原历史逐字节一致**（只改历史、不改代码）。
但在推送前，并行会话已经把原历史 push 到了 GitHub —— `1c8a6e8` 成为公开提交。

`[!]` 此时改它需要 force push，会顶掉并行会话与任何其它副本的本地仓库。
**收益是"翻历史时好不好懂"，代价是给正在同一个仓库干活的人添堵。** 取舍后选择保留原历史。

## 教训

`[!!]` **共享仓库里不要用 `git add -A`，只 stage 明确路径。**
在本仓库这一天里，`git add -A` 用过十几次都没出事 —— 只因为此前没有并行会话。
一旦有，它就会把别人的在途工作卷进自己的提交，**而且不会有任何提示**。
