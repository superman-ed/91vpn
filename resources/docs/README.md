## 这套文档到哪一步是"新手能照着做"的

诚实地说：**不是全部**。

| 章节 | 新手友好度 | 说明 |
|---|---|---|
| 02 快速开始 | ✅ **实测过** | 在一个全新 `git clone` 上从头跑到"面板能打开、节点能接上" |
| 03 面板部署 | ⚠️ 部分 | Cloudflare 后台的点击流程写了，但没有截图；域名 NS 要先托管到 Cloudflare 是硬前提 |
| 04 节点部署 | ⚠️ 部分 | 配置项表是全的；一键部署的前置（发布二进制）已并入 02 |
| 05–07 | ❌ 面向懂概念的人 | 中转、REALITY、接口 —— 假设你知道这些词是什么意思 |
| 08–10 | ⚠️ 参考向 | 查阅用，不是教程 |

`[!]` 如果你是第一次接触，**按 02 跑通一遍再读其余的**。
跑通之后那些概念会自己变得具体，比先读概念再动手快。

`[?]` 还缺的：一份术语表（REALITY / vless / 落地 / 中转 分别是什么），
以及 05–07 的"手把手"版本。

## 约定

文档里的标注沿用项目惯例：

| 标记 | 含义 |
|---|---|
| `[D]` | 动态验证过（真的跑起来看到了） |
| `[S]` | 静态确认（代码/二进制里读到的） |
| `[I]` | 推断，尚无直接证据 |
| `[?]` | 未知或未验证 |
| `[!]` | 值得注意的坑 |
| `[!!]` | 踩过的坑，或配错会静默出事的地方 |

`[!!]` 标记的段落**不要跳读** —— 它们记的都是"看起来正常、实际不对"的情形，
而这类问题不会自己暴露。

## 这份文档核对过什么

写完之后逐项对着代码与真机核对过，而不是凭印象写的：

- 配置键逐个比对 `agent/internal/config/load.go`
- 指标名逐个比对 `agent/internal/metrics/names.go`
- `install.sh` 的参数逐个比对脚本本身
- 观测端点在真节点上实际请求过（`/health` `/ready` `/metrics` 均 200）
- 引用到的文件路径逐个确认存在

`[!]` 核对中查出两处我写错的地方：把 `api_addr` 写成了配置文件的键
（它其实是 `install.sh --api-addr`），以及凭印象写了几个并不存在的指标名。
**文档里错误的命令比没有文档更糟** —— 照着抄却跑不通，人会先怀疑自己的环境。
