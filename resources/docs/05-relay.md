# 05 · 中转架构 —— 用户连香港、落地在日本

## 0. 什么时候需要中转

🎯 **一句话**:用户直连落地质量差(绕路、晚高峰丢包)时,在离用户近、线路好的地方(如香港)放一台中转,用户连香港、香港走优质线到日本,整体更快更稳。

**代价**:多一台机器的钱、多一跳延迟(通常远小于绕路省下的)、配置复杂度(这篇讲的就是它)。
**不需要中转**:直连本来就够好时。别为架构好看硬加。

---

## 1. 形态

```
客户端 ──→ 中转(香港)──→ 落地(日本)──→ 互联网
           转发规则监听      节点自身端口
```

中转做 **L4 透传**:不解协议、不认证用户,原样把字节搬给下一跳;用户的加密(vmess / vless+REALITY)在**落地**终结。"中转看不懂用户流量"既是安全性、也是下一节那条硬边界的由来。

---

## 2. `[!!]` D-1:中转不碰用户

| | 中转 | 落地 |
|---|---|---|
| 认证用户 | 否 | 是 |
| 持有用户名单与凭据 | **否** | 是 |
| 上报按用户流量 | **否**(按规则上报) | 是 |
| 进用户订阅 | 否(订阅发的是它的**入口地址**) | 是 |

面板在**读写两方向**都有守卫:`/mod_mu/users` 对中转返回空;`/mod_mu/users/traffic` 与 `/users/aliveip` 对中转直接拒绝。
`[!!]` 写方向那条是**计费面**:一台被接管的中转若能替任意用户记流量,能刷爆别人额度、或给自己免单。

---

## 3. 转发规则(概念)

后台 → **转发规则**。一条规则 = 一个**入站**(在哪些中转上监听什么端口)+ 若干**出站**(转给谁)。

| 概念 | 说明 |
|---|---|
| 入站类型 | `direct`(裸端口转发,不解协议)/ `vmess` / `vless` / `trojan` / `socks` |
| 入站节点集 | 这条规则在哪几台中转上生效 |
| 监听端口 | 单个、范围(`30001-30010`)或逗号列表 |
| 出站 | 目标地址:端口,或目标节点集;分 `primary` / `backup` 两池 |
| 均衡 | `roundrobin` / `random` / `leastping` … |
| 健康检查 | 间隔、连续失败/成功阈值 |

`[!]` 保存后**不是立刻生效**:中转要到下个拉取周期(默认 60 秒)才看到。列表「节点同步」列显示它到没到。

## 3b. 手把手:加一台中转

🎯 **目标**:已有一台落地(示例:节点 ID `12`,地址 `9.9.9.9:443`),在香港加一台中转,让用户连香港。

### 第 1 步 · 在面板建中转节点

节点管理 → 添加节点:名称 `香港中转`、**角色=中转**、地址填香港那台公网 IP、**端口=0**、协议/传输随便(中转不解协议)、等级门槛 `0`。
`[!]` **端口填 0 是对的**(不是漏填)——中转监听端口来自转发规则,面板列表会显示「端口见转发规则」。
`[!]` 想藏节点不给用户看,用**「排空/维护(enabled=false)」**,不是用很大的等级(表单等级只 0–9;排空的节点照常跑、只是不进订阅)。
保存后记下它的 **节点 ID** 与 **secret**。

### 第 2 步 · 装中转的 agent

和落地一样(见 [04](04-node-deploy.md)),节点 ID 换成中转那个。装完它去面板拉转发规则——现在还没有,所以它什么都不监听,**这是正常的**。

### 第 3 步 · 建一条转发规则

转发规则 → 新建:名称 `香港→日本01`、入站节点集勾「香港中转」、入站类型 `direct`、监听端口 `30001`(用户将连的端口)、出站目标选落地节点(或填 `9.9.9.9:443`)、**发 PROXY 头 = `2`**(想让落地看到真实客户端 IP 就开,见 §4)。
`[!]` 保存后下个周期(默认 60 秒)中转才看到;「节点同步」列显示到没到。

### 第 4 步 · 让落地收 PROXY 头

`[!!]` 上一步开了发头,这一步就**必须**做,否则用户连不上而两端都不报错。
落地节点编辑页 →「接受 PROXY 头」选**开启** → 保存。落地 agent 下个周期重启内核并开始收头。

### 第 5 步 · 锁住落地端口

`[!!]` 开了收头后,**任何能连到落地那端口的人都能伪造客户端 IP**,必须只放行中转。
用一键部署重装落地会**自动配**(它知道放行哪些中转 IP);手工见 §4 防火墙。

### 第 6 步 · 验证

`[!]` 本节六步**真机跑过一遍**,下面是真实会看到的东西。

1. **面板规则列表**:不该有**红色**(`reject`/`broken`)告警。
   `[!!]` 但你多半会看到**两条橙色 warn,是正常的**:
   - 「本规则不承载 UDP(出站发 PROXY 头,节点会关掉 UDP)」→ **正常**(开发头必然如此,见 §5)
   - 「落地的上报已过期」→ **刚建完规则时正常**(配对校验要落地近 5 分钟内的上报,等落地下个心跳就消失;一直不消才是问题)
2. 用户订阅里出现一条「日本01 · 香港中转」,地址是**香港 IP**、端口 `30001`。
3. 客户端连那条,能出网即成。
4. 落地的在线 IP 里看到的是**用户真实 IP**,不是香港中转的 IP——这验证 PROXY protocol 真生效了。

**✅ 对了吗**:①无红告警 ②订阅有"· 香港中转"那条 ③连得上 ④落地看到真实用户 IP。

**出问题时**:

| 现象 | 查什么 |
|---|---|
| 订阅里没中转那条 | 规则启用了吗?中转在线吗?(**离线的中转不进订阅**) |
| 连不上,两端日志都正常 | **PROXY 头配对**(最常见)——看规则页校验结果 |
| 校验报「这地址上有多台落地」 | 一个 IP 挂多台落地(不同端口),出站**目标端口**没对上——写成落地实际监听那个 |
| 连得上但落地看到的是中转 IP | 发头没开,或落地没收头 |
| 落地直连也能连上 | 落地端口没锁,见第 5 步 |

## 4. `[!!]` PROXY protocol:真实客户端 IP

🎯 **这步在干嘛**:中转透传后落地只看到中转 IP(所有用户都像同一 IP,统计/审计全废);PROXY protocol 在每条连接前加一小段头声明真实源地址。

**必须成对**:

| 中转出站 | 落地入站 | 结果 |
|---|---|---|
| `send_proxy_protocol = 2` | `accept_proxy_protocol = true` | ✅ 正确 |
| 发头 | 不收头 | ❌ 落地把头当协议数据 → 连不上 |
| 不发头 | 收头 | ❌ 落地等一个永不来的头 → 连不上 |

`[!!]` 配错的失败形态是**两端都不报错**(中转正常、落地一行没有,只有客户端知道)。规则页保存时做配对校验、把结果标在列表上——**唯一能在出事之前发现的地方**。
`[D]` v1 与 v2 不必匹配,收头端两版都认。

### 锁住落地端口

`[!!]` PROXY 头**无认证**:能连到落地端口的人可随意伪造客户端 IP,污染 alive_ip 与审计。开了 `accept_proxy` 的落地**必须只对中转可达**。
一键部署自动配防火墙(只放中转源 IP)。手工注意:
`[!!]` 机器归 ufw 管时**必须走 ufw**。往 INPUT 链尾追加 DROP 是**无效的**(ufw 的跳转排在前面,包在那被 ACCEPT 就走不到链尾)。实测踩过:规则形状完全对,端口照样对全世界开着。

---

## 5. `[!!]` UDP:两种情况完全不同

| 场景 | UDP |
|---|---|
| 用户流量(vless+vision 等)经中转 | **通** |
| 裸端口转发(`direct` 入站)+ `send_proxy_protocol` | **会被节点主动关掉** |

第一种通:vision 的 UDP 走 **XUDP 封装**,整条流包在那条 TCP 里,中转只看见 TCP。
第二种:`[D]` 实测 xray 把 PROXY 头当**独立数据报**先发、载荷在下个包 → 接收端整条 UDP 流**错位一个包**;而落地的 `acceptProxyProtocol` 是 **TCP sockopt**,UDP 路径上没有它,两端"正确配对"也剥不掉。所以 agent 主动摘 UDP 并告警、面板保存规则时提前提示。**UDP 不通是能被发现的故障,静默错位不是。** 要在这条规则上跑 UDP,就关掉 `send_proxy_protocol`(代价:丢真实客户端 IP)。

---

## 6. 订阅里给用户什么地址

🎯 **关键**:落地挂中转后面时,客户端要连的是**中转 IP + 转发规则监听端口**,不是落地自己的地址(落地那端口往往还被防火墙锁成只收中转)。

面板从转发规则**自动推导**:每条可达路径出一个订阅条目,名字带入口后缀(如「日本01 · 香港中转」);`accept_proxy` 的落地**不发直连条目**(那种端口直连必被拒);**离线的中转不出条目**(否则用户拿到连不上又无报错的死条目)。
`[!]` 不在节点上手填"对外地址",是因为那份数据会和规则各自演化——改了规则监听端口忘了回来改节点,订阅就静默失效。
