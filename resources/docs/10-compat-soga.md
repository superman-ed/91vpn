# 10 · 与 soga 的异同

本项目的 Agent 是 soga 的**独立实现**：行为对齐，代码无关。
这一篇讲对齐到什么程度、哪里故意不一样。

## 1. `[D]` 对照测试结果

同一个面板、两边各跑一个节点（详见 `compatibility/soga-vs-agent.md`）：

| 维度 | 结果 |
|---|---|
| 端点集合 | **一致** —— 同一组四个端点，1:1:1:1 的比例 |
| 调用频率 | 各自按配置的 `check_interval` / `submit_interval` |
| 用户名单拉取 | 一致 |
| 流量归属 | 一致（下载 2 MB → 用户账上 +2 MB） |
| 在线 IP 上报 | 一致 |
| 心跳字段 | 本 Agent 是**超集** |

`[!]` "端点集合一致"这一格能对上很重要：少打意味着功能缺失，
多打意味着给面板添了本不该有的负载 —— 两者都只有放在一起数才看得出来。

## 2. 配置兼容

`agent.conf` 与 soga 的配置文件**同构**，键名一致。从 soga 迁移时
通常只需换二进制。

`[!]` 遇到 soga 支持而本实现尚未实现的键，agent **启动即报错**，
不静默忽略（名单在 `agent/internal/config/sogakeys.go`）。
静默忽略会让人以为配置生效了 —— 那比不支持更糟。

## 3. 故意不一样的地方

| 项 | soga | 本实现 | 为什么 |
|---|---|---|---|
| 内核 | 子进程 | **嵌入为库** | 配置变更不必重启进程；内核崩溃不留孤儿进程（ADR-005） |
| 配置更新 | 全量重建 | **只下发变更** | 改一个用户不必让整条链路抖一下（ADR-001） |
| 上报失败 | `[?]` | **持久化队列，恢复后补报** | 面板短暂不可用不该丢账（ADR-004） |
| 计量口径 | `[?]` | **按线路字节** | 与机房账单口径一致（ADR-006） |
| 非法配置 | 部分容忍 | **启动即失败** | 静默降级会让人以为在按预期跑（ADR-003） |
| 授权校验 | 向作者服务器外呼 | **没有** | 本实现不需要授权 |
| 观测 | `[?]` | `/health` `/ready` `/metrics` | |
| 中转 | `[?]` | 转发规则 + 配对校验 + D-1 边界 | |

## 4. `[!!]` 关于 soga 的授权外呼

soga 启动时会向作者控制的四个域名 POST 一个**加密信封**。
里面装了什么无法确认（内容是加密的）。

`[D]` 授权校验失败**不中断进程** —— 用户同步、监听、上报全部继续。

做对照实验时，用 `--add-host` 把那四个域名指向 `127.0.0.1` 即可堵掉，
不影响实验有效性。

`[!]` 这是本实现**没有**的行为：本 Agent 不向任何第三方发起外呼。

## 5. 已知的协议侧限制（两边一样）

这些是 xray 内核的性质，不是实现差异：

- **vision 与 Mux 互斥**；对接 xray 内核的节点一律不要开 smux
  （Mihomo 的 smux 是 sing-mux，和 mux.cool 不是一个协议）
- **UDP 单包上限约 8 KiB**（`buf.Size = 8192`）
- **sspanel 路径下的 vless**：`[D]` soga 出不了 vless —— 这正是本项目
  用 `custom_config` 做扩展通道的原因（ADR-007）

## 6. 迁移清单

从 soga 换成本 Agent：

1. 面板不用改（契约一致）
2. 停掉 soga，装 agent（[04](04-node-deploy.md)）
3. `agent.conf` 沿用原 `soga.conf` 的键值
4. 启动后看是否有"未实现的配置键"报错 —— 有的话说明用到了尚未实现的功能
5. 对着 `/ready` 与面板心跳确认接上了

`[?]` 尚未对照的：用户增删改的同步时延、面板不可达时两边各自的行为、
内核崩溃后的自愈。想比的话，`compatibility/soga-vs-agent.md` §5 有复现步骤。
